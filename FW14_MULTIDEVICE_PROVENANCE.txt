FW14 MULTI-DEVICE HARNESS — PROVENANCE
======================================

The public-facing access page, one-time-code registry, device binding, child-process coordinator, evidence layout, and GitHub Pages companion were independently implemented in this workspace. No Sentrix HTML, JavaScript, styling, server code, naming, or GoldHEN binary was copied into this harness.

The supplied Sentrix raw13 source was previously frozen and inspected as an empirical comparison. Two profile values were adopted after analysis:

  slots = 9100000
  collection profile = drain:12

Those values remain in the byte-pinned child route because changing proven behavior merely to avoid a recognizable value would reduce correctness. The operator separately reported the comparison route working and later reported a visible GoldHEN load from the hardened child. Public artifacts deliberately omit local run identifiers, archive names, and evidence hashes.

The child route's security design is independent: source13 machine semantics, separate prepatch RW/RX aliases, exact credential restoration, 24 stock and 24 patched guard checks, verified cleanup, exploit retirement, then postpatch pthread dispatch of the pinned self-writing HEN.

GoldHEN is a separately authored payload. This repository pins the expected externally supplied image by SHA-256 but does not redistribute it; operators stage their own reviewed copy locally. It does not claim authorship of GoldHEN, the underlying public exploit lineage, or third-party research.

The correct claim is narrower: the reusable multi-device harness, hardened integration, access control, evidence protocol, and public UI are original implementations; external inputs and empirical influences remain attributed.
